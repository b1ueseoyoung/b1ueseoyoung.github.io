문제

오픈마켓을 여러 곳에서 운영하면 같은 상품의 CS와 리뷰가 채널별로 흩어집니다. 운영자는 엑셀과 관리자 화면을 오가며 세 가지에 직접 답해야 합니다.

  1. 지금 어떤 상품 속성의 불만이 늘었는가?
  2. 특정 채널만의 문제인가, 상품 전체의 문제인가?
  3. 실제 고객 표현과 상세페이지를 근거로 무엇을 고쳐야 하는가?

만든 것

쿠팡, 네이버, 지그재그에 흩어진 CS 문의와 상품 리뷰를 상품 단위로 통합하고, 고객이 반복해서 말하는 문제를 탐지해 원인과 개선안까지 연결합니다.

구성

Agent1 VoC 속성·감성 분류
속성 기반 감성 분석, 다중 라벨. JSON 출력을 Pydantic과 Enum으로 검증합니다.
Agent2 통계적 이상탐지와 원인 진단
최근 7일과 직전 28일을 비교합니다. 최소 표본 10건, Fisher 단측 정확검정, 상품별 BH-FDR 보정⁠(q=0.05), 최소 상승폭 3%p. 채널 패턴으로 편중형과 전역형을 판정합니다.
Agent3 근거 기반 개선안 생성
ChromaDB 검색⁠(RAG)⁠과 Tool Calling을 씁니다. 인용 문구가 실제 원문에 있는지 코드로 대조하고, 3관문 자기검증을 거칩니다. 셀러 피드백⁠(승인, 수정, 반려)⁠을 축적합니다.
리포팅
월간 리포트 PDF, CS 답변 가이드라인

Agent2가 알림을 내기까지 거치는 관문

  1. 7일과 28일 비교최근 7일을 직전 28일과 비교합니다.
  2. 최소 표본 10건데이터가 부족한 채널의 과도한 비율 변동을 막습니다.
  3. Fisher 단측 정확검정부정률이 오른 경우만 검정합니다.
  4. 상품별 BH-FDR 보정q=0.05. 여러 검정을 함께 할 때의 거짓 발견을 제어합니다.
  5. 최소 상승폭 3%p통계적으로만 유의한 미세한 변화를 뺍니다.

모두 통과하면 채널 패턴으로 편중형과 전역형을 판정하고, 고객 원문으로 원인을 진단합니다.

꿈도깨비 리뉴얼 — 아이가 주인공이 되는 AI 그림책

아이 사진과 선택을 반영해 아이가 주인공인 그림책을 만드는 웹 서비스
대상
7~9세 아이와 보호자
기술
React 18, Spring Boot 3.4, MySQL, FastAPI, codex CLI

하는 일

캡스톤 때 만든 꿈도깨비를 구조는 그대로 두고 다시 만들었습니다. 사진 1장으로 기준 캐릭터 후보를 만들고, 보호자가 승인하면 그 캐릭터가 이후 모든 장면의 참조가 됩니다. 장르와 장소를 고른 뒤 장면마다 선택지 3개 중 하나를 고르면 다음 장면의 글과 삽화가 만들어지고, 완성된 동화는 읽기 화면에서 낭독하고 책장에 보관합니다.

설계 원칙

  • 유료 API 키 없이 ChatGPT 로그인 상태의 codex로 글과 그림을 만듭니다.
  • 장면이 뜨면 선택지별 다음 장면을 미리 만들어, 고른 뒤 기다리는 시간을 줄입니다.
  • 거절, 시간 초과, 한도 소진 같은 실패 사유를 화면까지 전달하고 다음 행동을 보여 줍니다.
  • 기존 방식⁠(ComfyUI)⁠과 GPT Image 참조 방식 세 가지를 같은 조건으로 비교하는 실험 도구와 블라인드 검토 화면을 함께 만들었습니다.

품질 검증 — 삽화 속 얼굴이 사진과 닮았는가

사진 1장으로 만든 삽화에서 얼굴이 유지되는지 직접 측정했습니다. 기존 방식⁠(ComfyUI와 IP-Adapter)⁠ 2종과 GPT Image 참조 방식 3종을 같은 장면 5개로 비교하고⁠(그림 65장)⁠, 생성 방식을 프롬프트 개선, 얼굴 보정, 측정 후 재생성의 3단계로 고쳤습니다. 닮은 정도는 얼굴 인식 모델⁠(ArcFace)⁠로 잰 원본 사진과의 얼굴 유사도입니다.

사진 유사도 평균
0.34 → 0.51
0.45 이상인 칸
6/15 → 10/15
승인 캐릭터 유사도
0.67 → 0.73
그림 1장당 호출
1회 → 3.33회

현재 서비스 방식에서 개선 방식으로 바꿨을 때의 변화입니다. 유사도는 1이면 같은 얼굴, 다른 사람끼리는 0.0 안팎이고, 실사 사진의 같은 인물 판정 기준은 0.30~0.45입니다. 승인 캐릭터 유사도는 한 권 안에서 같은 인물로 유지되는지를 봅니다.

결과와 한계

  • 효과가 있던 것: 사진과 승인 캐릭터를 함께 참조하고 닮음 우선, 얼굴 묘사, 미화 금지를 넣은 프롬프트, 그리고 구도와 표정은 두고 얼굴만 사진에 맞게 다시 그리는 보정입니다. 보정은 얼굴이 작은 전신과 옷이 바뀐 장면에서 가장 크게 올랐습니다.
  • 채택하지 않은 것: 사진만 참조하면 수치는 더 높았지만 미소가 무표정으로 바뀌고 지시에 없는 옷이 나왔습니다. 반실사 화풍과 구도 규칙은 효과가 없었습니다.
  • 재현: 웃음과 옆얼굴 단서 문장만 더한 같은 3단계 방식을 독립적으로 한 번 더 돌려도 0.51이 나왔습니다. 단서 문장 자체의 효과는 없었습니다. 생성 실패⁠(거절, 시간 초과)⁠는 306번 호출 중 0건입니다.
  • 남은 문제: 옆모습⁠(0.29)⁠과 눈을 감고 크게 웃는 표정⁠(0.449)⁠은 0.45에 못 미쳤습니다. 정면 사진과 비교하는 측정 방식의 한계도 섞여 있습니다.
  • 한계: 성인 1명, 사진 1장의 결과입니다. 후보 선택과 평가에 같은 지표를 써서 수치가 낙관적이고, 사람 평가는 하지 않았습니다. 보호자 동의를 받은 아이 사진 여러 장으로 다시 검증할 계획입니다.

Claude Code 플러그인 (별도 서버 없음)

하는 일

답변 중에는 고양이가 걷다가 가장자리에서 방향을 바꾸고, 승인 대기 중에는 멈추며, 답변이 정상으로 끝나면 춤을 한 번 춥니다. 함께 도는 뽀모도로 타이머는 25/5/15분, 집중 4회마다 긴 휴식이고, /focus-cat 명령으로 시작, 일시정지, 건너뛰기, 고양이⁠(A, B)⁠ 선택을 합니다.

Focus Buddy — 집중하는 동안 옆에서 잠드는 고양이

맥 메뉴 막대와 화면 위 작은 위젯에서 도는 픽셀 고양이 뽀모도로 앱
실행
macOS Apple Silicon 메뉴 막대 앱 (소스를 받아 직접 빌드)
기술
Electron, React, TypeScript, Swift⁠(AppKit)⁠, Bun

하는 일

집중 25분, 휴식 5분, 집중 4회마다 긴 휴식 15분으로 돌고, 50/10/20분 프리셋이나 직접 정한 시간도 쓸 수 있습니다. 남은 시간은 메뉴 막대에 늘 보이고, 원하면 화면 위 위젯을 켭니다. 집중하는 동안 고양이는 자면서 5분마다 코를 골고, 휴식이 되면 깨어나 기지개를 켠 뒤 쉽니다. 오늘 한 집중은 할 일 이름과 함께 기록됩니다.

설계 원칙

  • 타이머는 하나만 두고, 메뉴 막대, 위젯, 기본 화면이 같은 상태를 봅니다.
  • 다음 단계로 저절로 넘어가지 않고, 직접 눌러 시작합니다.
  • 앱을 끄거나 맥이 잠들면 진행 중인 세션을 일시정지해 저장하고, 다시 켜면 이어 합니다.
  • Electron 메뉴 막대 아이콘이 화면에 보이지 않는 문제를 Swift⁠(AppKit)⁠로 만든 작은 도우미로 풀었습니다.

빙글빙글 그림책 — 문장이 무기가 되는 뱀서류 게임

쓰러뜨린 살림살이 도깨비가 떨군 낱말로 문장을 지으면, 그 문장이 그대로 무기가 되는 브라우저 게임
실행
브라우저에서 바로 플레이 (데스크톱 권장, 휴대폰은 화면을 끌어 조작)
기술
바닐라 JavaScript, Canvas 2D, WebAudio, Bun

하는 일

꿈도깨비의 마스코트 부기가 밤마다 그림책을 먹어 치우는 도깨비로 나오는 뱀서류⁠(Vampire Survivors류)⁠ 게임입니다. 레벨업 때 고른 낱말이 '서영이의 고무신이 빙글빙글 돌았어요' 같은 문장이 되고, 그 글자가 그대로 탄환이 되어 날아갑니다. 밤이 끝나면 고른 문장과 움직인 길로 그 밤의 그림책 한 권이 만들어지고, 판을 거듭할수록 부기의 과거 페이지 6장과 엔딩 2개로 이어지는 이야기가 열립니다. 엽전으로 사는 영구 강화, 단어장 해금, 내기 보상이 누적 성장 요소입니다.

설계 원칙

  • 한국어 의태어의 소리가 무기 규칙입니다. 빙글빙글은 크고 느리고 세며, 뱅글뱅글은 작고 빠르고 많고, 삥글삥글처럼 더 센 소리가 되면 진화합니다. 쓰는 낱말은 모두 표준국어대사전에서 확인했습니다.
  • 게임 로직을 화면과 분리해서, 자동 플레이 봇으로 생존 시간, 클리어율, 카드 선택률을 시뮬레이션해 밸런스를 맞췄습니다.
  • 엔진과 오디오 파일 없이 만들어 첫 화면이 바로 뜨고, 적 1,000마리를 띄운 측정에서도 프레임이 떨어지지 않았습니다.
빙글빙글 그림책 게임 하기 빙글빙글 그림책 마지막 밤부터 보기

2주차 과제로 만든 게임입니다. '마지막 밤부터 보기'는 평가용 저장 칸으로, 페이지 6장과 마지막 밤이 열린 상태에서 엔딩까지 바로 볼 수 있습니다. 진행은 이 브라우저에만 저장됩니다. 캐릭터와 배경 그림은 AI 이미지 생성으로 그렸습니다.
